# When does row 11, column 8 first become nonzero? · [中文版](README.zh-CN.md)

Put $T=2^{2048}$. In the increasing enumeration of the critical points generated by an I3 embedding,

$$
J_{11}(\gamma_3)=\gamma_T,\qquad 11 *_T 8=0,\qquad 11 *_{T+1}8=2^T.
$$

The table $A_m$ has $2^m$ elements, represented by residues modulo $2^m$. Projection shows that row 11, column 8 vanishes at every order $m\le T$. The critical-point identity holds for each I3 witness, which is an explicit argument to the Lean theorem. [Paper proof](proof.md) · [Final Lean theorem](lean/RankSteelEndpoint.lean) · [Finite-table criterion](lean/Gamma11Endpoint.lean)

## Proof and verification

- `j11_gamma3_exact` proves the critical-point identity. `finite_table_reading_of_I3` gives the corresponding entries of the ordinary finite tables. The set-theoretic argument uses Steel's theorem to derive unbounded first-row periods. [I3 and its critical spectrum](lean/RankI3.lean) · [Steel reduction](lean/RankSteelReduction.lean)
- The 103 local modules consist of 100 core modules and three final Steel modules. The final declarations report only `propext`, `Classical.choice` and `Quot.sound`. [Core replay](verification/check-20261118-core-final.log) · [Final replay](verification/check-20261118-complete-endpoint.log)
- The paper includes six appendices. The accompanying bounded check tests the bit blocks and the order-lift calculations on small tables. [Program](checks/first_four_period_audit_20261118.py) · [Results](checks/first_four_period_audit_20261118.json)

In the Atlas source build, two proofs in the upstream `SetLanguage` module retain their subtype quantifiers by using `simp [-Subtype.forall, Fin.snoc]`. All 62 adapted dependencies and all 103 local modules were rebuilt and replayed by the kernel. The local part of the new log matches the two original transcripts after newline normalization. The manifest also records the upstream hash from before the change. [Complete source rebuild](verification/atlas-rebuild.log) · [Source adaptation](prepare_steel.py) · [Hashes](verification/sources.json)

## Reproduce the checks

From this directory, Python 3.10 or later can verify the source hashes, replay inventories and final axiom reports.

~~~sh
python -B check.py
~~~

For a kernel rebuild, use Lean **4.33.1**, the shared finite-table project, and a matching Mathlib build that includes `Mathlib.SetTheory.ZFC.VonNeumann`. The required Mathlib commit is `eba3d887fc52c98627f4b81507c0efc3096e91b9`. The Steel sources come from FrenzyMath/LaverTable at `1f5ee8c0f6dee8fe25f8971371ff6533dca0a707`. [Shared project](../../laver_table_lower_bounds/lean/README.md) · [Mathlib source](https://github.com/leanprover-community/mathlib4/tree/eba3d887fc52c98627f4b81507c0efc3096e91b9) · [Upstream Steel theorem](https://github.com/frenzymath/LaverTable/blob/1f5ee8c0f6dee8fe25f8971371ff6533dca0a707/LaverTables/Algebra/Steel.lean)

~~~sh
python -B ../../laver_table_lower_bounds/lean/build.py --lean-bin /path/to/lean/bin
python -B check.py --rebuild --lean-bin /path/to/lean/bin --mathlib /path/to/mathlib4 --upstream /path/to/LaverTable
~~~

If Mathlib's dependency builds live in a separate Lake package directory, add `--packages /path/to/.lake/packages`. The builder parameterizes the upstream set universe and checks the reconstructed sources against the manifest before compiling and replaying them. Outputs go in `.build/`. [Manifest](verification/sources.json) · [Source preparation](prepare_steel.py) · [Verifier](check.py)

The same command can be split into independent first stages. `--part steel` checks 62 dependencies and `--part core` checks the 100 core modules. With both sets of objects in the same build directory, `--part endpoint` checks the last three modules and the theorem with its explicit I3 hypothesis.
